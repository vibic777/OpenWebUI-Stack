# Справочник команд Open WebUI Stack (`openwebui-stack`)

В этом каталоге находятся команды обслуживания Docker Compose стека Open WebUI.
Команды работают со стеком из `openwebui-stack`; локальные настройки читаются из его `.env`.
Для справки по конкретной команде вызывайте `./имя-команды.sh --help` или `-h`.

## Безопасный порядок действий

1. Начинайте с read-only диагностики: `./verify-stack.sh`, `./show-stack-deployment.sh` и отдельные `./check-*.sh`.
2. Для планируемых изменений сначала используйте `--dry-run`, если команда его поддерживает.
3. Перед обновлением или изменением данных создайте резервную копию: `./backup-stack.sh`.
4. Для рутинной уборки файлов используйте `./cleanup-chat-files.sh` без флагов, проверьте список, затем выберите срок хранения и запустите с `--delete --older-than DAYS`. Не используйте `--yes`, пока не проверили процедуру.
5. `wipe-rag.sh` и `--volumes` — глобальная очистка. Она может удалить Knowledge и не заменяет уборку чатовых файлов.
6. `restore-stack.sh` заменяет текущую базу; без `--yes` попросит ввести точную фразу подтверждения. Проверьте каталог резервной копии и манифест перед восстановлением.

## Команды управления стеком

| Команда | Назначение и мягкий режим |
|---|---|
| `deploy-stack.sh` | Первичное развертывание. `--init` создаёт `.env` и секреты, не затирая существующий `.env`; `--dry-run` показывает план; `--offline` использует локальные образы; `--portainer` добавляет отдельный Portainer. |
| `start-stack.sh` | Запуск остановленных сервисов. `--dry-run` показывает Compose-команду. |
| `stop-stack.sh` | Остановка контейнеров без удаления томов. `--dry-run` показывает команду. |
| `update-stack.sh` | Обновление образов и пересоздание сервисов. По умолчанию спрашивает подтверждение; `--dry-run` показывает план, `--offline` запрещает скачивание. |
| `backup-stack.sh` | Бэкап PostgreSQL и данных; режим `--full` включает Qdrant и SeaweedFS и кратко останавливает соответствующие сервисы для копирования. `--dry-run` показывает план. |
| `restore-stack.sh` | Восстановление из каталога бэкапа; разрушительно заменяет текущую базу и выбранные тома. Сначала читайте `--help`, проверяйте backup и запускайте без `--yes`. |
| `verify-stack.sh` / `full-test.sh` | `verify-stack.sh` проверяет базовые сервисы и включённый reranker; выключенный reranker помечает `SKIP`. Для reranker выполняется функциональная проба. `--all` дополнительно проверяет DB/S3/Qdrant. `full-test.sh` имеет отдельные режимы; E2E режим создаёт и удаляет тестовые данные. |
| `show-stack-deployment.sh` | Показать Compose-конфигурацию и образы работающего стека; диагностика без изменений. |


## Слои и резервные копии образов

| Команда | Назначение |
|---|---|
| `images-save.sh` | Сохранить Docker-образы в архивы для переноса на сервер без интернета. |
| `images-load.sh --from DIR --check` | Проверить контрольные суммы и наличие образов без их загрузки. Без `--check` загружает образы из каталога. |
| `enable-rerank.sh` / `disable-rerank.sh` | Включение или отключение reranker-слоя и Compose overlay. |
| `start-portainer.sh` / `stop-portainer.sh` / `update-portainer.sh` | Отдельное управление Portainer. |
| `image-transition.sh`, `update-openwebui-current.sh`, `update-openwebui-ghcr.sh` | Переход/обновление только образа Open WebUI; команды описывают собственные варианты rollback в `--help`. |

## Проверки сервисов

`check-postgres.sh`, `check-valkey.sh`, `check-qdrant.sh`, `check-seaweedfs.sh`, `check-embeddings.sh`, `check-rerank.sh`, `tika-check.sh`, `check-e2e-rag.sh` и `list-models.sh` проверяют отдельные компоненты или интеграции. Большинство проб read-only; проверки Qdrant и SeaweedFS могут создать и затем удалить временную тестовую запись. Перед запуском конкретной проверки посмотрите её `--help`.

## Файлы, Knowledge и необратимые команды

| Команда | Действие |
|---|---|
| `cleanup-chat-files.sh` | Предпросмотр/очистка старых файлов, связанных только с чатами. Knowledge, каналы, заметки, общие файлы и история чатов защищены. См. [CHAT-CLEANUP-RU.md](CHAT-CLEANUP-RU.md). |
| `wipe-rag.sh --list` | Только просмотр коллекций Qdrant и объектов S3. Не удаляет данные. |
| `wipe-rag.sh --vectors/--files/--all` | Удаляет все коллекции и/или объекты, включая Knowledge. Нужны backup и явное подтверждение. |
| `wipe-rag.sh --volumes` | Удаляет тома Qdrant и SeaweedFS целиком; самое широкое разрушительное действие. |

## Остальные утилиты

Скрипты настройки Nginx, UFW, названия Open WebUI и установки расширений имеют собственную справку: `./nginx-upload-limit.sh --help`, `./configure-ufw.sh --help`, `./brand-openwebui.sh --help`, а для каждой функции — соответствующий `install-functions.sh --help` или `remove-functions.sh --help`.

Некоторые `.py` внутри `functions/` — исходники самих функций Open WebUI, а `build_*.py` — внутренние генераторы пакетов. Они не являются командами управления стеком. Тестовые файлы запускаются тестовым раннером и не должны менять стек при запросе help.

## Общие примеры

```bash
# Посмотреть состояние и конфигурацию развертывания
./verify-stack.sh
./show-stack-deployment.sh

# Спланировать обновление, пока ничего не меняя
./update-stack.sh --dry-run

# Сохранить базу перед изменениями и проверить интеграции
./backup-stack.sh --db-only --keep 14
./verify-stack.sh --all

# Проверить кандидатов на рутинную очистку, без удаления
./cleanup-chat-files.sh --older-than 30
```
