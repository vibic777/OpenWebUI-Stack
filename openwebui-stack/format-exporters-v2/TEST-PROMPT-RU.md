# Тестовые промты экспортёра V2

Промты ниже предназначены для проверки меню и скачивания файлов в Open WebUI. Можно запускать их по одному. После ответа нажмите нужную кнопку класса и выберите указанный формат. Чтобы проверить множественную выгрузку, используйте соответствующий промт с двумя или тремя артефактами. Имя файла должно содержать UTC-штамп времени и порядковый номер для нескольких файлов.

### DXF

```text

**Ожидается:** IMG → DXF скачивает два `.dxf`. Откройте их в CAD или CorelDRAW и проверьте, что присутствуют замкнутый контур и окружность.

### PNG, JPG и WebP

SVG можно выгрузить напрямую или преобразовать в выбранный растр. Для PNG/JPG/WebP сначала используются готовые изображения в сообщении; если их нет, экспортёр берёт SVG из fenced-блоков или SVG-разметки и рендерит в браузере. WebP также можно сделать из PNG/JPG.

```text
Создай и прикрепи к ответу две отдельные простые картинки: синюю окружность на белом фоне и оранжевую звезду на белом фоне. Верни каждую картинку отдельным изображением в сообщении, не объединяй их в одну картинку.
```

**Ожидается:** по одному файлу на каждый найденный растр; если растровых изображений нет, каждый SVG преобразуется в выбранный формат. Например, два SVG в ответе и выбор PNG дают два `.png`, выбор JPG — два `.jpg`, выбор WebP — два `.webp`. Проверь каждый формат отдельно, нажимая IMG на одном и том же SVG-ответе. Реальную генерацию изображений можно проверить дополнительно; для SVG-конверсии она не требуется.

```text

На кадрах один синий круг движется слева направо по четырём позициям; подпиши кадры FRAME 1, FRAME 2, FRAME 3, FRAME 4. ```

**Ожидается:** IMG → «GIF — анимация из кадров» скачивает один анимированный `.gif`. Проверьте воспроизведение и последовательность четырёх кадров. GIF строится из нескольких SVG или изображений, имеет ограниченную палитру и рассчитан на простые короткие анимации.

## DOC — документы

### DOCX — один документ

```text
Составь краткий структурированный отчёт «Проверка DOCX». Добавь заголовки «Цель», «Результат», два маркированных пункта и заключение. Используй русский текст.
```

**Ожидается:** один файл `.docx` с содержимым ответа.

### PPTX — одна презентация

```text
Подготовь короткую презентацию на три слайда «Проверка PPTX»: титульный слайд, слайд «План» с тремя пунктами и слайд «Итог» с одной фразой. Верни обычную структурированную разметку с заголовками слайдов.
```

**Ожидается:** один файл `.pptx` на весь ответ. Открой его в PowerPoint или совместимом просмотрщике.

### PDF — печать браузера

```text
Составь одностраничную памятку «Проверка PDF» на русском: заголовок, короткий абзац и три пункта списка. Не используй широкие таблицы.
```

**Действие и результат:** DOC → «PDF документа (текст ответа)». Экспортёр открывает штатную печать форматированного текстового ответа. В диалоге выберите «Сохранить как PDF» и сохраните файл.

### XLSX: отдельная книга для каждой таблицы

```text
Выведи в ответе две независимые Markdown-таблицы. Первая таблица с заголовками «Товар» и «Количество» и строками «Карандаш | 3», «Ручка | 5». Вторая с заголовками «Город» и «Код» и строками «Москва | MSK», «Казань | KZN». Между таблицами поставь заголовки «Склад» и «Города». Не используй code fences.
```

**Действие:** DOC → «XLSX — отдельная книга на каждую таблицу».

**Ожидается:** два `.xlsx`, каждый содержит одну таблицу на одном листе. Открой обе книги и проверь данные.

### XLSX: одна книга, все таблицы по листам

**Действие:** DOC → «XLSX — одна книга, таблицы по листам».

**Ожидается:** один `.xlsx` с двумя листами, на каждом соответствующая таблица.

### VSDX

```text
Выведи ровно две Mermaid-диаграммы в отдельных fenced-блоках с меткой mermaid. Первая: flowchart TD, Start --> Review --> Done. Вторая: flowchart LR, Input --> Validate --> Save. Не объединяй диаграммы и не добавляй другие блоки mermaid.
```

**Ожидается:** DOC → VSDX скачивает два `.vsdx`, по одному на диаграмму. Открой файлы в Visio или просмотрщике VSDX и проверь, что схема отображается.

### Draw.io (.drawio)

```text
Выведи ровно две независимые редактируемые схемы diagrams.net в двух fenced-блоках с меткой drawio. Каждый блок должен содержать полный корректный XML-документ с корнем <mxfile>, внутри <diagram> и <mxGraphModel>. Первая схема: блоки «Старт» → «Проверка» → «Готово». Вторая схема: блоки «Ввод» → «Обработка» → «Результат». Для каждой схемы используй mxCell для вершин и соединений, уникальные id внутри файла и mxGeometry для расположения. Не добавляй пояснения внутрь XML, не используй внешние изображения или ссылки и не добавляй другие блоки drawio.
```

**Ожидается:** DOC → «Draw.io (.drawio) — редактируемая схема» скачивает два отдельных файла `.drawio`. Откройте оба в draw.io / diagrams.net, проверьте подписи и соединения, затем попробуйте переместить блок и сохранить файл. Экспортёр принимает только XML с корнем `<mxfile>` и элементом `<diagram>`.

### BPMN (.bpmn)

```text
Выведи ровно два отдельных XML-файла BPMN 2.0 в fenced-блоках с меткой bpmn. Каждый файл должен иметь BPMN namespace, корень <definitions>, один <process> с startEvent, task, endEvent и двумя sequenceFlow. Добавь BPMNDiagram, BPMNPlane, BPMNShape с Bounds для всех трёх элементов и BPMNEdge с Waypoint для обеих стрелок, чтобы схема имела координаты и открывалась визуально. Первый процесс: «Приём заявки» → «Проверка» → «Решение». Второй: «Получить заказ» → «Собрать» → «Отправить». Используй уникальные id внутри каждого файла. Не добавляй других блоков bpmn.
```

**Ожидается:** DOC → «BPMN (.bpmn) — процессная схема» скачивает два файла `.bpmn`. Откройте их в BPMN Modeler (например, совместимом с BPMN 2.0) и проверьте узлы, стрелки и расположение. Экспортёр проверяет XML-структуру, но саму BPMN-схему не перерисовывает и не исправляет.

### Markdown и TXT

```text
Составь короткий отчёт с заголовком «Проверка экспорта», подзаголовком «Результат», одним нумерованным списком из двух пунктов и заключительным предложением «Тест завершён». Не используй таблицу и code fences.
```

**Действия и результат:** DOC → Markdown скачивает один `.md` с исходным текстом ответа; DOC → Текст скачивает один `.txt` с тем же содержанием.

| Power Query (.m) | `Выведи ровно один блок m: let Source = #table({"Value"}, {{"M ONE"}}) in Source.` | `Выведи ровно два блока m с самостоятельными выражениями let...in: таблица со значением M ONE и таблица со значением M TWO.` |

**Ожидается:** одиночная колонка создаёт один файл, колонка «Два файла» — два файла. VBA и QBasic сохраняются как `.bas`, Pascal и Delphi/Object Pascal — как `.pas`; метки различаются, поэтому совпадающие расширения не смешивают блоки. SH принимает метки `bash`, `sh` и `shell`.

PlantUML и Graphviz DOT выгружаются как редактируемые исходные файлы `.puml` и `.dot`; экспортёр не запускает рендереры.

**Ожидается:** два файла одного формата получают общий временной штамп и суффиксы `-01`, `-02`. PlantUML и DOT сохраняются как исходники `.puml` и `.dot`; Power Query сохраняет выбранное `.pq` или `.m`. QBasic/VBA и Pascal/Delphi остаются раздельными по выбранному пункту меню.

## DATA — структурированные данные

У каждого следующего промта запрашивайте два fenced-блока с нужной меткой. Проверяйте один блок (один файл) и два блока (два файла). Экспортёр валидирует поддерживаемый синтаксис и при ошибке сообщает номер некорректного блока.

| Выбранный формат | Промт для двух валидных блоков |
|---|---|
| JSON | `Выведи ровно два fenced-блока json: первый {"id":1,"name":"Alpha"}, второй {"id":2,"name":"Beta"}.` |
| JSONL | `Выведи ровно два fenced-блока jsonl. В первом две строки JSON: {"id":1} и {"id":2}. Во втором одна строка JSON: {"id":3}.` |
| XML | `Выведи ровно два fenced-блока xml. Первый: <items><item id="1"/></items>. Второй: <items><item id="2"/></items>.` |
| YAML/YML | `Выведи ровно два fenced-блока yaml с простыми отображениями: id: 1 и name: Alpha; затем id: 2 и name: Beta.` |
| TOML | `Выведи ровно два fenced-блока toml: первый содержит [app] и name = "Alpha", второй [app] и name = "Beta".` |
| INI | `Выведи ровно два fenced-блока ini: первый [app] с name=Alpha, второй [app] с name=Beta.` |
| CONF | `Выведи ровно два fenced-блока conf с настройками mode=alpha и mode=beta, по одному на блок.` |
| ENV | `Выведи ровно два fenced-блока env: первый APP_NAME=alpha, второй APP_NAME=beta.` |
| Properties | `Выведи ровно два fenced-блока properties: первый app.name=alpha, второй app.name=beta.` |
| CSV | `Выведи ровно два fenced-блока csv. В первом: name,count затем alpha,1. Во втором: name,count затем beta,2.` |
| TSV | `Выведи ровно два fenced-блока tsv с заголовками name и count и одной строкой alpha / 1 или beta / 2, разделяй поля табами.` |

Для YAML в одном ответе используй либо метку `yaml`, либо `yml`. Для Properties указывай точную метку `properties`; для TSV — `tsv` и настоящие табы между колонками.

### CSV/TSV из Markdown-таблиц

```text
Не используй fenced-блоки csv или tsv. Выведи две Markdown-таблицы с двумя колонками каждая: первая name/count со строкой alpha/1, вторая name/count со строкой beta/2.
```

**Действия:** DATA → CSV, затем DATA → TSV на том же ответе.

**Ожидается:** если нет соответствующих fenced-блоков, каждая Markdown-таблица экспортируется отдельным файлом выбранного разделителя.

## Проверка одиночного совпадения

Для любого поддерживаемого формата попросите модель вывести ровно один соответствующий артефакт. Экспорт должен скачать ровно один файл без суффикса `-02`. Это относится в том числе к DATA, CODE, изображению, таблице XLSX и Mermaid-диаграмме.

## Проверка имён и границ

- Один файл получает временной штамп в имени; несколько файлов одного ответа имеют общий штамп и порядковые номера.
- PNG/JPG/WebP проверьте на SVG fenced-блоках и на реальных PNG/JPG изображениях. Изображения должны открываться; одного текстового описания картинки недостаточно.
- XLSX общего режима должен открываться как одна книга с несколькими листами; split-режим — как несколько книг.
- DOCX и PPTX должны скачиваться по одному файлу; PDF открывает печать браузера и сохраняется через «Сохранить как PDF».
- Нажатие кнопки работает с сообщением ассистента, под которым нажали её.
- Если браузер спросит разрешение на несколько загрузок, разрешите его для Open WebUI.
