# Справка: список моделей и сквозная RAG-проверка

## Какой ключ нужен

Для `list-models.sh` и `full-test.sh --e2e-rag` нужен API-ключ администратора **Open WebUI**. Создайте его в интерфейсе Open WebUI: аватар пользователя → **Настройки** → **Аккаунт** → **API Keys**. Нужен токен Open WebUI, не `WEBUI_SECRET_KEY`, не пароль Docker/PostgreSQL/Qdrant и не ключ провайдера модели.

Сквозной тест обращается к самому Open WebUI, поэтому отдельный ключ LM Studio/провайдера в тест вводить не нужно. Open WebUI сам использует уже настроенные подключения для чат-модели и embeddings. Адрес сервера embeddings и ключ провайдера читаются из локальной конфигурации Open WebUI; ключ провайдера в тест передавать не нужно.

## Безопасно передать API-ключ

Предпочтительный вариант — ввести токен скрыто в текущем терминале:

```bash
read -rsp 'Open WebUI admin API key: ' OPENWEBUI_API_KEY; echo
export OPENWEBUI_API_KEY
```

Либо хранить токен в закрытом файле и указать путь, не помещая секрет в командную строку:

```bash
chmod 600 /secure/path/openwebui-api-key
export OPENWEBUI_API_KEY_FILE=/secure/path/openwebui-api-key
```

Файл должен содержать только токен (допустим завершающий перевод строки). При наличии `OPENWEBUI_API_KEY` он имеет приоритет над файлом. Скрипты не печатают значение токена. Не добавляйте токен в Git и не присылайте его в чат.

`WEBUI_URL` читается из `openwebui-stack/.env`. Если вывод сообщает, что API вернул HTML вместо JSON, проверьте адрес `WEBUI_URL`, reverse proxy и доступность именно `/api/models` или другого указанного `/api/...` пути: вероятно, запрос попал на страницу входа/ошибки или не в тот виртуальный хост.

Если при загрузке большого файла появляется `Unexpected token '<'` и Nginx отвечает `413 Request Entity Too Large`, это лимит тела запроса в reverse proxy. Проверить активный лимит и безопасную 2-МБ пробу можно так:

```bash
sudo ./nginx-upload-limit.sh get --probe-size 2m
```

Для файла около 50 МБ установите, например, 100 МБ:

```bash
sudo ./nginx-upload-limit.sh set 100m
```

Команда спросит подтверждение `[y/N]`: введите `y` и нажмите Enter. Просто Enter означает отмену. `--yes` подтверждает заранее; `--dry-run` только показывает план.

При `get` скрипт читает загруженную конфигурацию командой `nginx -T`, показывает выбранный vhost/файл и, если задан `--probe-size`, отдельно посылает синтетический HTTPS-запрос. При `set` он редактирует только найденный активный server-блок, сохраняет резервную копию, запускает `nginx -t`, затем при успехе делает reload. Если проверка или reload не проходят, восстанавливает конфиг из копии.

`nginx -T` здесь нужен для чтения активной конфигурации; он сам по себе не проверяет подготовленное изменение. `nginx -t` проверяет изменённый конфиг. Reload происходит только после успешного `nginx -t`. `full-test.sh` ничего не меняет и не перезагружает: он запускает read-only пробу на 2 МБ. Повторите её после `set`:

```bash
sudo ./nginx-upload-limit.sh get --probe-size 2m
sudo ./full-test.sh
```

Проба не создаёт файл и не требует API-ключа. Ответ `401` с JSON означает, что запрос дошёл до API Open WebUI (прокси пропустил тело); `413` означает, что лимит всё ещё мал. Другой HTML/ошибка указывает на неверный vhost/URL, TLS или промежуточный прокси — смотрите код ответа и Content-Type.

Состояние файлов важно различать: шаблон `nginx/openwebui.conf` задаёт `client_max_body_size 100m`, но сам по себе не устанавливает конфигурацию на хосте. Фактическое состояние проверяйте через `get`.

## Получить доступные модели и выбрать чат-модель

Из каталога `openwebui-stack`:

```bash
./list-models.sh
```

Команда использует тот же API-ключ и печатает ID моделей, видимых Open WebUI. Для генерации ответа в E2E нужен чат-ID; embedding- и reranker-модели не подходят. Укажите нужный ID из списка:

```bash
export OPENWEBUI_E2E_MODEL='ID-ИЗ-ВЫВОДА-list-models.sh'
./full-test.sh --e2e-rag
```

Без `OPENWEBUI_E2E_MODEL` скрипт возьмёт первую модель, которую вернёт Open WebUI. Чтобы запустить только обычные интеграционные проверки и отдельно получить каталог моделей:

```bash
./full-test.sh --list-models
```

## Что проходит сквозной тест

Тест создаёт небольшой временный DOCX с уникальным маркером, загружает его в Open WebUI, ждёт извлечения текста, проверяет embeddings и индексацию в Qdrant, запрашивает hybrid retrieval с активными настройками Open WebUI, затем вызывает чат с прикреплённым файлом и проверяет, что ответ содержит маркер. В конце он удаляет тестовый файл и его векторы. Если тест оборвался до очистки, удалите файл `openwebui-rag-e2e-*` из Workspace → Files.

Нужна роль администратора, потому что проверка читает эффективную RAG-конфигурацию. Скрипт намеренно не отключает TLS-проверки.

Удалить токен из среды после проверки:

```bash
unset OPENWEBUI_API_KEY OPENWEBUI_API_KEY_FILE OPENWEBUI_E2E_MODEL
```
