# Памятка пользователю: как попросить ответ для экспорта

Эта памятка для пользователей Open WebUI. Выберите нужный формат в Action-меню под ответом ассистента. Экспортёр сохраняет подходящий текстовый блок или преобразует ответ/изображение в файл; он не запускает полученный код и не проверяет его на правильность по смыслу.

## Как пользоваться

1. Скопируйте подходящий запрос из этой памятки в чат. Замените квадратные скобки своими данными.
2. Проверьте ответ: содержимое файла должно быть в отдельном блоке с тремя обратными кавычками и меткой языка/формата, например ` ```json ` или ` ```python `. Не просите модель утверждать, что файл уже скачан.
3. Под ответом нажмите Action нужной группы и выберите расширение.
4. Откройте скачанный файл подходящей программой. Если блок неверный или выбран не тот формат, попросите модель исправить блок и повторите экспорт.

Кнопки групп различаются цветом и короткой меткой: IMG — изображения, DOC — документы, CODE — программный код, DATA — данные и конфигурации.

Просите только нужные блоки: так меньше шанс выбрать не тот код или конфигурацию, если в ответе несколько фрагментов одного типа.

## 1. Изображения: SVG, PNG, JPG, WebP

### Векторный SVG из текста

```text
Создай простую чистую SVG-инфографику на тему «[тема]». Верни только один самодостаточный SVG-документ в отдельном блоке кода с меткой svg. Размер 1200×800, светлый фон, читаемые русские подписи, аккуратные фигуры и линии. Не используй JavaScript, внешние файлы, внешние шрифты, foreignObject или встроенные ссылки. Не добавляй объяснений до и после блока.
```

После ответа выберите изображение → SVG. SVG — векторная графика, обычно остаётся чёткой при масштабировании.

### PNG, JPG или WebP из настоящего изображения

```text
Создай изображение: [подробно опишите сцену, стиль, композицию, нужные надписи и соотношение сторон]. Нужен именно растровый файл изображения, не описание и не код SVG.
```

Когда модель прикрепила/показала реальное изображение, выберите Action изображений и нужное расширение. PNG/JPG/WebP экспортируются из изображения, доступного в сообщении Open WebUI. WebP в браузере получается конвертацией растрового PNG/JPG; один только текстовый SVG-блок или словесное описание не является растровым изображением. Если чат-модель не умеет создавать изображения, приложите готовый PNG/JPG-файл. SVG экспортируйте отдельным текстовым блоком, как в примере выше.

## 2. Документы: DOCX, XLSX, PPTX, VSDX, PDF, Markdown, TXT

### DOCX, PDF, TXT или Markdown

```text
Подготовь [тип документа] на тему «[тема]» для [аудитория/цель]. Пиши по-русски, ясно и без выдуманных фактов. Структура: заголовок; краткое резюме; разделы [перечислите]; выводы; список действий. Используй Markdown-заголовки и списки, без таблиц, если они не нужны. Если данных не хватает, обозначь это как «Нужно уточнить». Выведи готовый материал в сообщении, не утверждай, что файл уже создан.
```

Затем под ответом выберите документы → DOCX, PDF, TXT или Markdown. PDF строится без внешних Python-библиотек. Если в образе есть TTF-шрифт, кириллица сохраняется в скачиваемом PDF; если шрифта нет, функция откроет штатное окно печати браузера — выберите «Сохранить как PDF».

### XLSX из таблицы

```text
Составь таблицу для Excel по теме «[тема]». Верни Markdown-таблицу с колонками: [названия колонок] и [число] строками данных. Каждая строка должна иметь одинаковое число ячеек. Не объединяй ячейки; даты пиши в формате ГГГГ-ММ-ДД, числа — без единиц измерения в той же ячейке. Неизвестные значения помечай «Не указано», не выдумывай их. Не добавляй другие таблицы.
```

Выберите документы → XLSX. Экспортёр использует таблицу ответа; перед скачиванием проверьте заголовки и строки.

### PPTX из плана презентации

```text
Подготовь содержание презентации на [число] слайдов для [аудитория] на тему «[тема]». Для каждого слайда выведи Markdown-заголовок `## Слайд N — Название`, затем 2–5 коротких пунктов списка. В конце добавь заметки докладчика отдельным абзацем с меткой «Заметки докладчика:». Не используй таблицы. Не выдумывай факты; места, требующие проверки, помечай «Уточнить».
```

Выберите документы → PPTX. Сначала убедитесь, что слайды отделены заголовками и пункты расположены под правильным слайдом.

### VSDX (Visio) из схемы

```text
Опиши процесс «[название процесса]» как Mermaid flowchart, который можно преобразовать в Microsoft Visio. Выведи только один блок ```mermaid. Используй `flowchart TD`, 5–7 коротко подписанных узлов: обычные узлы только в квадратных скобках `[Шаг]`, решения только в фигурных скобках `{Условие?}`, связи только `-->`. У решения обязательно подпиши выходы `Да` и `Нет` с помощью `-->|Да|` и `-->|Нет|`. Добавь возвратную связь, если она нужна процессу. Не используй `subgraph`, стили, классы, клики, HTML, sequenceDiagram и директивы. Не придумывай бизнес-правила: неизвестные условия обозначь как `[Уточнить условие]`.
```

Затем выберите документы → VSDX. Локальная функция строит файл Visio из ограниченного Mermaid, а не просит модель написать внутренности VSDX. Проверьте итоговый файл в Microsoft Visio: генерация файла не гарантирует правильность процесса или идеальную раскладку. При проблеме сначала попросите модель упростить схему до 5–7 узлов и простых стрелок.

## 3. Языки программирования

Во всех запросах укажите язык, среду и версию, попросите один отдельный блок с точной меткой языка. Код при экспорте сохраняется как текст и не запускается.

### Python

```text
Напиши небольшую программу на Python 3.11 для [задача]. Требования: [входные данные], [ожидаемый результат], обработка пустого/ошибочного ввода, комментарии к нетривиальным местам. Используй только стандартную библиотеку. Верни только один полный исходный файл в блоке ```python, без Markdown-обрамления внутри блока и без пояснений вокруг.
```

### PowerShell

```text
Напиши безопасный скрипт PowerShell 7 для [задача] в Windows. Укажи параметры как переменные в начале, добавь проверку входных значений и понятные сообщения об ошибках. Не удаляй и не перезаписывай данные без явного параметра-подтверждения. Верни один полный файл в блоке ```powershell, не добавляй пояснений вокруг.
```

### Bash

```text
Напиши Bash-скрипт для Linux [дистрибутив/задача]. Добавь `#!/usr/bin/env bash`, `set -euo pipefail`, проверку аргументов и безопасную обработку пробелов в путях. Не используй сетевую загрузку и разрушительные команды без явного подтверждения. Верни один полный файл в блоке ```bash.
```

### VBA для Microsoft Office

```text
Напиши VBA-макрос для [Excel/Word/PowerPoint] версии [версия], который [задача]. Уточни, какой объект/лист/документ обрабатывается. Не используй скрытые внешние вызовы, сетевой доступ или удаление файлов. Верни полный модуль VBA одним блоком ```vba, включая необходимые объявления и обработку ошибок. Перед запуском напомни пользователю проверить макрос и выполнять его только если он доверяет коду.
```

### JavaScript, TypeScript, PHP, HTML, CSS и другие

Замените `[метка]` точной меткой нужного блока: `javascript`, `typescript`, `php`, `html`, `css`, `java`, `c`, `cpp`, `csharp`, `go`, `rust` или `sql`.

```text
Подготовь один законченный файл на [язык и версия] для [среда/платформа], который [задача]. Вход: [вход]. Результат: [результат]. Не добавляй сторонних зависимостей без необходимости. Если код может менять или удалять данные, сначала добавь безопасный режим/предварительный просмотр. Верни только один полный блок кода с меткой ```[метка], без пояснений до или после.
```

Для SQL тестируйте на синтетических данных; укажите диалект (например, PostgreSQL) и просите только запрос, который соответствует цели. Экспорт не запускает и не проверяет код на безопасность.

## 4. Данные и конфигурации

Используйте этот запрос для JSON, JSONL, XML, YAML/YML, TOML, INI, CONF, ENV, `.properties`, CSV и TSV. Укажите, какой формат нужен; если формат построчный (JSONL), попросите по одному JSON-объекту на строку.

```text
Преобразуй следующие сведения в валидный [формат] для [назначение/программа]. Сохрани значения без изменений, не добавляй неизвестные факты. Неизвестные поля пропусти [или укажи null — выберите нужное]. Используй кодировку UTF-8. Верни только один блок ```[метка формата] с содержимым файла, без комментариев и пояснений внутри блока. Для CSV используй заголовок и запятые; для TSV — заголовок и табуляцию. Для JSON выведи корректный JSON без trailing comma. Для XML соблюдай единый корневой элемент.

Данные:
[вставьте данные]
```

Замените `[метка формата]` на `json`, `jsonl`, `xml`, `yaml`, `toml`, `ini`, `conf`, `dotenv`, `properties`, `csv` или `tsv`. Затем выберите Action данных и то же расширение. Формат `CONF` не имеет единого стандарта: в запросе обязательно назовите программу, которая будет читать конфиг.

### Мини-пример одних данных в разных форматах

Данные: номер заявки 42, статус «создана».

JSON:

```json
{"ticket":42,"status":"создана"}
```

YAML:

```yaml
ticket: 42
status: создана
```

CSV:

```csv
ticket,status
42,создана
```

## Советы и ограничения

- Если кнопки нужной группы нет, сообщите администратору: возможно, соответствующая Action-функция ещё не установлена или не включена.
- Когда ответ содержит несколько кодовых блоков одного языка, попросите модель оставить ровно один блок перед экспортом.
- Если экспортёр сообщает об ошибке, не переименовывайте расширение вручную: исправьте содержимое исходного блока.
- Не отправляйте в чат пароли, ключи, токены, персональные или другие секретные данные. Используйте вымышленные данные для учебных примеров.
- Просматривайте сгенерированные скрипты, VBA и SQL до использования. Факт успешного скачивания не означает, что код безопасен или верен.
- Если модель не умеет выдавать изображение, используйте вложенный файл; текстовый ответ не заменит растр PNG/JPG/WebP.
