# Полный тест всех форматов

Скопируйте этот запрос целиком в новый чат. После ответа проверяйте Actions по очереди: DOC, CODE, DATA и IMG.

~~~text
Подготовь единый демонстрационный ответ для полного тестирования Open WebUI Actions: DOC, CODE, DATA и IMG.

Строго соблюдай правила:
1. Не добавляй пояснений до или после тестовых данных.
2. Каждый fenced-блок должен быть отдельным.
3. Для каждого указанного языка или формата создай ровно один блок.
4. Не объединяй разные форматы в один блок.
5. Все данные должны быть минимальными, валидными и безопасными.
6. Не утверждай, что файлы уже созданы или скачаны.

РАЗДЕЛ 1. ДОКУМЕНТЫ

Сначала выведи:
- заголовок "# Полный тест экспорта";
- два коротких абзаца на русском;
- нумерованный список из трёх пунктов;
- Markdown-таблицу с колонками ID, Название, Статус и двумя строками;
- заголовки "## Слайд 1 — Проверка" и "## Слайд 2 — Результат", под каждым по 3 пункта;
- один Mermaid-блок для VSDX:

~~~mermaid
flowchart TD
    A[Начало теста] --> B[Подготовка данных]
    B --> C{Проверка успешна?}
    C -->|Да| D[Экспорт завершён]
    C -->|Нет| E[Исправить данные]
    E --> B
~~~

РАЗДЕЛ 2. CODE

Создай ровно по одному отдельному fenced-блоку с точной меткой для каждого формата:
powershell, bash, python, vba, javascript, typescript, php, html, css, java, c, cpp, csharp, go, rust, sql.

Каждый блок должен содержать только минимально валидный безопасный код. Код не должен удалять файлы, обращаться к сети или менять реальные данные. SQL должен содержать только безопасный SELECT по синтетическим данным.

РАЗДЕЛ 3. DATA

Создай ровно по одному отдельному fenced-блоку с точной меткой для каждого формата:
json, jsonl, xml, yaml, toml, ini, conf, env, properties, csv, tsv.

Используй одни и те же данные:
номер заявки: 42
статус: создана
ответственный: Иван Петров

Требования:
- JSON должен быть валидным;
- JSONL — по одному JSON-объекту в каждой строке;
- XML — с одним корневым элементом;
- YAML, TOML и INI — синтаксически корректные;
- ENV — только строки KEY=VALUE;
- Properties — строки key=value;
- CSV — с заголовком и запятыми;
- TSV — с заголовком и табуляцией;
- внутри блоков не должно быть пояснений и комментариев.

РАЗДЕЛ 4. IMG

Создай один самодостаточный SVG-блок с точной меткой svg. В SVG должны быть размер 800×500, светлый фон, заголовок, прямоугольник, круг, соединительная линия и русские подписи. Не используй JavaScript, внешние ссылки, внешние шрифты, foreignObject или обработчики событий.

PNG, JPG и WebP нельзя имитировать текстом или SVG. Если модель умеет генерировать изображения, отдельно создай настоящее растровое изображение. Иначе эти три формата проверяются на приложенном PNG/JPG-файле.
~~~

## Как проверять результат

- DOC: DOCX, XLSX, PPTX, VSDX, PDF, Markdown, TXT;
- CODE: каждый язык отдельно;
- DATA: каждый формат отдельно;
- IMG: SVG из ответа, PNG/JPG/WebP на настоящем изображении.

Для CODE и DATA выбирайте формат, соответствующий метке блока. Если появляется сообщение «найдено 0», модель не вывела нужный fenced-блок с точной меткой.
