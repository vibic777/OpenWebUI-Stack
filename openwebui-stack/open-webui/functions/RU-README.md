# Плагины (Functions) для Open WebUI

Эти Functions используют библиотеки, уже включённые в образ Open WebUI (python-docx, openpyxl, python-pptx, fpdf2 и шрифты Noto), а также стандартную библиотеку Python. Установщик не использует `requirements:` и не устанавливает пакеты через pip.
Установщик не загружает Python-пакеты. Если в образе нет нужной библиотеки, функция сообщит имя отсутствующего модуля.

| Файл | Тип | Что делает |
|---|---|---|
| `export_office.py` | Action, **11 кнопок** | **DOCX**, **XLSX**, **PPTX**, **VSDX**, **PDF**, **MD**, **TXT**, **CSV**, **SVG**, **PNG**, **JPG**. Экспорт кода и конфигураций доступен в пакетах `format-exporters/` и `format-exporters-v2/`. |
| `token_and_time.py` | Filter | под ответом: токены in/out, итог, секунды, ток/с и итог по чату |
| `message_timestamps.py` | Filter | дата и время каждого сообщения видны всегда (не только при наведении) |

Кириллица, латиница и китайский поддерживаются (PDF — шрифты Noto из образа; DOCX/PPTX объявляют восточно-азиатский шрифт).

Установка и удаление: [README.md](../README.md) и [RU-README.md](../RU-README.md). Инструкции экспортёров: [format-exporters](../../format-exporters/README.md) и [format-exporters-v2](../../format-exporters-v2/README.md).

## Установка (без интернета)

Автоматически (рекомендуется), из папки стека на сервере:

```bash
cd openwebui-stack/open-webui
./install-functions.sh --email admin@example.com --ask-password
```

Удаление: из этого же каталога запустите `./remove-functions.sh --all`.

Вручную: Admin → **Functions** → **+ New** → вставить файл → Save → включить **Active** и **Global**.
После этого под каждым ответом появятся кнопки **DOCX / XLSX / PPTX / VSDX / PDF / MD / TXT / CSV / SVG / PNG / JPG** (значки под сообщением).

Плагины лежат в PostgreSQL: их сохраняют `backup-stack.sh` / `restore-stack.sh` и переживают переразвёртывание стека (одна БД).
Обновить плагин: заменить `.py`, запустить установщик ещё раз.

## Как получить хороший результат

| Нужно | Что попросить у модели |
|---|---|
| XLSX | «Ответь **таблицей** markdown» — каждая таблица станет листом; числа станут числами |
| PPTX | «Сделай структуру презентации: заголовки `##` = слайды, под ними маркированные пункты» |
| VSDX | «Нарисуй схему процесса как **mermaid flowchart** (`flowchart TD`, узлы `A[Текст]`, ветвления `B{Вопрос?}`)» |
| DOCX / PDF | любой markdown-ответ: заголовки, списки, таблицы, код |
| TXT | любой ответ; Markdown-оформление преобразуется в обычный текст |
| CSV | markdown-таблица → UTF-8 CSV; нужна хотя бы одна таблица |
| SVG | один блок ```svg``` или SVG-разметка; активное содержимое и внешние ссылки блокируются |
| PNG / JPG | встроенные base64-данные изображения или внутренний файл Open WebUI; внешние URL не загружаются |

Valves (Admin → Functions → ⚙): `scope` = `last_message` (по умолчанию: сообщение, у которого нажали кнопку) или `all_messages` (весь чат);
`pdf_font_dir` — только если шрифты не находятся автоматически.

## Ограничения (честно)

- **VSDX** пишется вручную как OPC-пакет (офлайн-библиотеки для Visio нет). Пакет проверен структурно и через Apache Tika, но не проверялся открытием в Microsoft Visio. Соединители — линии со стрелкой, не «приклеены» к фигурам; автораскладка слоями (сверху вниз / слева направо), возможна ручная правка.
  Понимается только mermaid `flowchart` / `graph`.
- PPTX: простой макет (заголовок + текст, таблицы по 9 строк); без картинок и диаграмм.
- PNG/JPG ограничены 20 МиБ, SVG — 2 МиБ; SVG проверяется на активное содержимое и внешние ресурсы.
- Скачивание внутренних файлов идёт из текущей сессии Open WebUI; внешние URL не запрашиваются.
- Если в будущем образе Open WebUI пропадёт библиотека, кнопка покажет понятную ошибку с именем модуля.

Снять: Admin → Functions → ⋯ → Delete. Никогда `down -v`.
